# 三栏目重置设计

## 目标

在规则审核、运行中心、候选结果三个页面分别提供一个明确的“重置”入口。每次重置都需要二次确认，并在完成后立即刷新当前页面，用户不需要手动刷新浏览器。

## 数据边界

### 规则审核重置

规则是运行与候选判断的上游。为避免留下引用不存在规则版本的运行和结果，本操作清空当前岗位的规则版本、岗位变化、搜索计划、搜索战役、运行记录、候选结果、AI 判断和人工复核，并将岗位恢复到“尚未生成规则”的状态。岗位本身、岗位名称、原始 JD 和上传文件保留。

页面显示空状态，并提供“重新生成规则”操作，从保留的岗位原始资料生成新的 v1 草稿。

### 运行中心重置

清空当前岗位的搜索计划、搜索战役、运行任务、断点、快照、策略决策和历史运行记录。已批准/草稿规则保留，候选结果保留，便于用户只重新设计并执行搜索。

活动任务需要先在数据库事务内标记停止，再由级联删除任务明细，避免扩展继续领取已删除任务。

### 候选结果重置

清空当前岗位的候选人、规则评估、DeepSeek searchFit、人工复核和任务—候选关联。规则、搜索方案、任务历史及任务计数保留；结果页立即回到空状态。新建 fresh run 后仍可重新读取候选人。

## 接口

- `POST /api/jobs/:jobId/reset/rules`
- `POST /api/jobs/:jobId/reset/runs`
- `POST /api/jobs/:jobId/reset/results`
- `POST /api/jobs/:jobId/rules/regenerate`

重置接口返回各类删除数量，岗位不存在返回 404；数据库变更全部在事务中执行。规则重新生成复用现有 DeepSeek 岗位包生成逻辑，只允许在当前规则版本为 0 时调用。

## 界面

每个栏目标题区域放置红色次级按钮：

- 规则审核：`重置规则与全部下游数据`
- 运行中心：`重置运行中心`
- 候选结果：`清空候选结果`

确认对话框使用不同文案，明确是否保留规则、候选或岗位原始资料。请求期间禁用按钮；成功后清理对应 React 状态、刷新岗位摘要并显示删除统计；失败时保留原页面状态并显示错误。

## 验证

后端测试覆盖三类重置的保留/删除边界、岗位不存在、事务一致性和规则重新生成前置条件。前端测试覆盖三个按钮、确认步骤和对应 API。完整执行单元/API 测试、类型检查、构建与 lint；真实 Meshy 数据只验证按钮显示和普通搜索流程，不实际点击重置。
