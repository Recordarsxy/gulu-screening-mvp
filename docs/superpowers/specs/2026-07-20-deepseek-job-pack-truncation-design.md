# DeepSeek 岗位包截断恢复设计

## 目标

让真实 Meshy AI 岗位要求能够稳定生成完整岗位包，同时保持调用次数、成本和失败行为可控。

## 方案

- 通用 JSON 调用继续默认使用 1,800 token，避免影响候选人分析和连接测试。
- 岗位包生成首次使用 4,000 token。
- 当上游明确返回 `finish_reason: length` 时，抛出可识别的 `response_truncated` 错误。
- 岗位包仅针对 `response_truncated` 自动重试一次，第二次使用 7,000 token。
- 鉴权、限流和网络错误不自动重试；截断、空响应、无效 JSON、无效结构和原样返回空模板仅重试一次。
- 生成结果必须在摘要、理想候选人、条件、行业、公司、职位、证据、搜索计划和问题中至少有两个维度相对默认模板发生实质变化，否则视为 `invalid_job_pack`。
- AI 生成的年龄、性别等受保护硬筛条件自动移入忽略项；学历、城市、地区和年限等需要确认的条件自动降级为软条件并生成待确认问题。
- AI 输出中的 `[已确认]` 标记不受信任；只有后续人工编辑才能建立已确认硬条件。
- 两次都截断时沿用现有岗位创建失败路径，不保存半成品岗位；前端保留原始输入。

## 接口边界

`DeepSeekProvider.generateJson` 新增可选的 `maxTokens` 参数；未传时保持 1,800。`generateJobPack` 封装岗位包专属额度与一次重试，并在返回前调用 `normalizeAiDraftRules` 生成可供人工审核的安全草稿，调用方接口不变。

## 验收

- 单元测试证明首次截断后只重试一次，额度依次为 4,000 和 7,000。
- 单元测试证明非截断错误不重试。
- 单元测试证明原样返回默认模板会携带失败原因用 7,000 token 重试，而不是创建空岗位。
- API 测试证明 AI 擅自生成的年龄硬筛被忽略，城市、学历和年限硬筛被降级为软条件，岗位草稿仍可创建。
- 全量测试、类型检查、Lint 和生产构建通过。
- 使用 Meshy AI 海外销售经理原始客户需求在网站中成功生成岗位草稿。
- 生成结果保留北京/上海/深圳、海外 B2B、vibe coding、阿里云类目标公司以及缺失信息待确认原则。
