# 原子化自适应搜索设计

## 问题

战役步骤可能在同一字段保存多个备选值，例如五家基金公司。谷露的标签控件会逐次替换这些值，最终只保留最后一个值，而预检仍要求全部值同时存在，导致任务以 `campaign_filters_unverified` 停止，且不会读取候选人。

## 设计

任务启动时把每个字段的第一个值作为实际搜索值；同字段其余值继续保留在已确认战役中，作为后续备选，而不是一次提交给谷露。运行规则固定为：结果数为 1–100 时读取；大于 100 时保留现有条件并增加另一维度的单个值；等于 0 时优先替换同维度备选值，之后再尝试其他未测试组合；全部组合耗尽才进入下一步骤。

DeepSeek只负责生成候选搜索方向和分析简历匹配度。网页筛选、计数、候选遍历、去重和状态推进均由确定性的扩展与服务器状态机执行。

## 安全与失败处理

每次搜索继续使用 `savedSearchId=94096`，并在读取前拒绝任何 owner 条件或 `type=contact`。实际 URL 必须与当前原子筛选一致；无法验证时停止读取并记录错误。任务不得读取联系方式、照片、备注或附件，也不得执行谷露写操作。

## 验收

- 多值公司步骤启动后，实际任务步骤只有第一家公司。
- 宽结果会增加不同维度条件，不会替换当前种子值。
- 空结果会换到同维度下一个备选值。
- 1–100 个结果会开始读取候选人。
- 自动化测试、类型检查、构建和 lint 全部通过，并完成一次真实谷露运行验证。
