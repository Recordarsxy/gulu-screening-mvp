# 谷露筛选 MVP v1.2.0：岗位变化、搜索方案导入与两轮进度设计

## 目标

解决正式任务在公司轮读取若干人后切换岗位轮时缺少明确反馈的问题，并允许招聘需求随时间演进、允许粘贴同事提供的公司轮或岗位轮方案。所有变化都使用版本记录，正在运行的任务保持原有规则和搜索条件不变。

## 已确认的产品原则

- 岗位变化生成新的规则版本，不覆盖原始 JD 或旧版本。
- 当前运行中的任务继续使用启动时锁定的规则和搜索方案；新版本只用于下一次任务。
- 公司轮结束后自动、立即进入岗位轮。
- 同事方案支持粘贴自然语言或聊天记录，由 DeepSeek 整理成结构化标签，再由用户人工编辑和确认。
- 修改已确认的搜索标签会把方案恢复为待确认，并重新要求 dry-run 和 5 人试跑。
- v1.1.0 保留为回退版本，v1.2.0 完成验证后发布。

## 根因与修复方向

真实 SQLite 状态显示，最近两次正式任务均在公司轮读取 7 人后切换到岗位轮；岗位轮返回 0 人，任务随后被标记为 completed。界面只显示累计读取数和当前轮次，未显示每轮结果与“岗位轮 0 人已完成”，因此用户感知为卡住。

v1.2.0 不把该问题处理成单纯文案补丁，而是为每一轮保存独立状态与读取计数。扩展在公司轮完成后安排一次近即时续跑，不等待常规 30 秒轮询。岗位轮无结果也会生成明确的轮次完成记录。

## 领域模型

### 岗位变化记录

新增 `JobChangeNote`：

- `id`
- `jobId`
- `text`
- `createdAt`
- `appliedRuleVersion`，未整合时为空

原始文本只存本机 SQLite。整合操作把原始 JD、当前已批准规则和一条或多条未应用变化交给 DeepSeek，生成新的规则草稿。用户必须在规则审核页面批准新版本后才能生成新的谷露搜索方案。

### 搜索方案来源与版本

`GuluSearchPlan` 增加：

- `version`：岗位内递增的搜索方案版本
- `sourceNotes`：用户粘贴的同事方案原文，默认为空
- `createdAt` 与 `updatedAt`

DeepSeek 将 `sourceNotes` 与当前已批准岗位包共同整理为公司轮和岗位轮。用户仍可逐项编辑关键词、公司、职位、城市、行业和职能。任何结构化筛选字段变化都会创建或保存为 draft，并重置发布验证状态。

任务启动时保存完整方案快照或方案版本引用，保证后续编辑不改变运行中的任务。

### 两轮任务状态

`GuluConnectorTask` 增加：

- `planVersion`
- `companyStatus` 与 `roleStatus`：`pending | running | completed | empty | failed`
- `companyReadCount` 与 `roleReadCount`

任务状态流为：

1. 公司轮准备
2. 公司轮读取
3. 公司轮完成或空结果
4. 岗位轮准备
5. 岗位轮读取
6. 岗位轮完成或空结果
7. AI 分析完成，任务完成

公司轮结束后，扩展保存轮次完成事件和断点，并创建约 1 秒后的单次续跑闹钟。常规轮询仍作为恢复后备。每个候选人的游标继续在读取后保存。

## 界面

### 岗位变化

规则审核页增加“岗位变化”面板：

- 多行文本输入，可粘贴客户反馈或新的时间要求。
- “保存变化”只记录原文。
- “整合为新版本”调用 DeepSeek 生成新的规则草稿。
- 显示历史记录、时间及应用到的规则版本。
- 若有运行中的旧版本任务，显示“当前任务继续使用 vN，新版本将用于下一任务”。

### 同事搜索方案

运行中心增加“粘贴同事搜索方案”面板：

- 接受自然语言、聊天记录或逐行内容。
- “DeepSeek 整理标签”生成公司轮和岗位轮草稿。
- 生成后使用现有结构化编辑器人工增删标签。
- 已确认方案提供“编辑方案”入口；编辑后立即回到 draft。

### 两轮进度

任务卡片分别展示公司轮和岗位轮：

- 等待、运行、已完成、0 人完成或异常。
- 当前页码与每轮读取人数。
- 累计去重数、已分析数和 Token。
- 岗位轮为 0 人时显示“岗位轮已完成，没有匹配结果”。

## 接口

新增：

- `GET /api/jobs/:jobId/changes`
- `POST /api/jobs/:jobId/changes`
- `POST /api/jobs/:jobId/changes/integrate`
- `POST /api/jobs/:jobId/gulu-plan/import`

现有 `PUT /api/jobs/:jobId/gulu-plan/confirm` 继续用于人工确认结构化标签。计划编辑后的保存会保留 draft 状态并重置 rollout。

扩展事件接口新增 `round_started` 和 `round_completed` 事件。`round_completed` 包含轮次、读取数和是否空结果，但不包含联系方式或禁止字段。

## 异常与恢复

- 单名候选人读取失败重试一次，仍失败则跳过并记录。
- 连续三次失败、登录失效、验证码、权限不足或页面结构变化时暂停。
- 轮次准备超时转换为明确的 `needs_attention`，不无限显示运行中。
- Edge 刷新、扩展休眠或服务重启后从任务的轮次、页码和候选游标恢复。
- 任务完成后保留两轮独立计数和状态。

## 安全边界

- 所有 AI 行为仅调用 DeepSeek。
- 原始方案和岗位变化保存在本机 SQLite，不提交 GitHub。
- DeepSeek 仍只接收批准规则、岗位变化文本和脱敏候选经历。
- 扩展继续禁止读取手机、邮箱、Wechat、地址、照片、备注和附件。
- 扩展继续禁止谷露写操作、下载、批量勾选、联系候选人或绕过验证码。

## 验收标准

- 公司轮读取 7 人后自动开始岗位轮，无需用户点击或等待常规轮询。
- 岗位轮 0 人时任务正常完成，页面明确显示岗位轮 0 人。
- 岗位轮有结果时继续读取，并分别累计两轮人数。
- 刷新 Edge 或扩展休眠后从正确轮次与游标恢复。
- 岗位变化生成新规则版本且不改变正在运行的旧任务。
- 自然语言同事方案可以生成两轮结构化标签，并允许人工修改。
- 修改已确认方案后回到待确认，dry-run 与 pilot 状态重置。
- 完整类型检查、自动化测试、生产构建、真实 dry-run 和 5 人试跑通过。
