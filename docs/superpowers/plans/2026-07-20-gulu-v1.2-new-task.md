# Gulu v1.2 New Task Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a confirmed fresh formal-run workflow that resets connector search state while preserving task-scoped history and results.

**Architecture:** Keep `gulu_tasks` as immutable run snapshots, add a task-to-candidate membership table, and extend the existing REST endpoints rather than creating a second task system. The React run center switches to the newly created task and exposes prior runs in a collapsed history panel. The extension recognizes a new task ID and navigates to the fixed candidate-list URL before applying round-one filters.

**Tech Stack:** TypeScript, Express, SQLite, React, Chrome/Edge Manifest V3, Vitest.

## Global Constraints

- All AI behavior continues to use DeepSeek only.
- A fresh formal run still requires an approved rule pack, confirmed plan, completed dry-run, and completed pilot.
- One active real Gulu task per job; prior tasks, candidates, reviews, and login state are never deleted.
- The extension remains read-only and keeps its existing restricted permissions.
